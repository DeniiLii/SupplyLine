Форма: `reg.fintechacademy.ru/submitsolution` («Загрузка решения»). Семь обязательных полей. Ниже готовые тексты и порядок действий. Числа в квадратных скобках `[...]` подставляются из `deliverables/numbers.json` после работы код-агента; больше ничего менять не нужно.

## 1. Тексты для полей

### Название проекта
```
SupplyLine
```

### Краткое описание проекта
Основной вариант (≈330 знаков):
```
SupplyLine — цифровая платформа реверсивного факторинга для среднего бизнеса (выручка 0,8–2 млрд ₽). Крупный покупатель подтверждает счёт, платформа выкупает требование по формуле от риска покупателя, поставщик получает деньги в течение суток. Работающий прототип на синтетических данных: цена, лимиты, реестр против двойной продажи, финансовая модель.
```
Короткий вариант, если поле ограничено (≈170 знаков):
```
SupplyLine: цифровой реверсивный факторинг для среднего бизнеса. Покупатель акцептует счёт, платформа платит поставщику в течение суток. Прототип на синтетических данных.
```

## 3. Видео на 2–3 минуты: сценарий

Запись автоматическая (`scripts/record_demo.py`), закадровый текст необязателен. Субтитры идут на экране. Кадры:

| Время | Экран | Что видно |
|---|---|---|
| 0:00–0:15 | Титул + дисклеймер | «SupplyLine: от акцепта покупателя до денег у поставщика менее чем за 24 часа. Демо на синтетических данных» |
| 0:15–0:45 | Симулятор цены | Эффективная ставка 19,67%, плашка «Дороже кредита МСП на 1,67 п.п.», разбор дисконта на четыре части |
| 0:45–1:10 | Лента счетов, счёт «КРУПНЫЙ» | Кнопка «Продать счёт» заблокирована лимитом концентрации с объяснением |
| 1:10–1:40 | Обычное предложение | Продажа, затем попытка повторной продажи — реестр блокирует двойное финансирование |
| 1:40–2:10 | +1 день, просрочка, +30 дней | Деньги у поставщика, просрочка якоря, регресс к поставщику |
| 2:10–2:40 | Портфельная модель | Стресс-тест якоря, рычаги окупаемости, ворота фазы 0 |
| 2:40–2:55 | Финал | Ссылки: демо и репозиторий; «Прототип. Не банк, не оферта» |

Текст закадрового голоса (по желанию, 1–2 предложения на кадр) агент кладёт в `docs/VIDEO_SCRIPT.md`.

## 4. Порядок ваших действий

1. Дать код-агенту `02_CODE_AGENT_SPEC.md` (положить файл в корень распакованного проекта и написать: «Выполни ТЗ из 02_CODE_AGENT_SPEC.md; сначала прочитай 01_AUDIT_AND_STRATEGY.md; папка `analytics/` рядом с ТЗ»).
2. Когда агент попросит: создать репозиторий на GitHub (пустой, публичный) и выполнить `git remote add origin ... && git push -u origin main --tags`.
3. Выбрать хостинг по `docs/DEPLOY.md`, задеплоить, сообщить агенту URL; агент запустит `scripts/smoke.py`.
4. Загрузить `deliverables/` на облачный диск по структуре из раздела 2, открыть три ссылки в режиме «инкогнито»: файл открывается без входа.
5. Подставить три ссылки и числа `[N]` в тексты раздела 1; вставить тексты в форму.
6. Нажать «Отправить решение». Сделать скриншот подтверждения.

## 5. Чек-лист перед отправкой

- [ ] Демо открывается в режиме «инкогнито» и показывает дисклеймер сверху.
- [ ] Две вкладки-посетителя: «+30 дней» в первой не меняет часы во второй.
- [ ] Видео воспроизводится, длительность 2–3 минуты, размер до 100 МБ.
- [ ] Презентация открывается в PowerPoint, 14–16 слайдов, есть слайд «Результаты Спринта №1».
- [ ] В презентации, видео и форме одинаковые числа (из `numbers.json`).
- [ ] Репозиторий публичный, README, CI зелёный, нет секретов (`git grep -nEi "(api[_-]?key|secret|token|password)"`).
- [ ] В папке аналитики нет ошибок Excel (`#REF!`, `#DIV/0!`).
- [ ] Нет настоящих логотипов и названий банков в стилизации интерфейса.
- [ ] Заменены все `[...]` в текстах формы.
- [ ] Отправка выполнена, скриншот подтверждения сохранён.

## 6. Если до дедлайна не успевается всё

Минимум для корректной отправки: репозиторий + README + видео-демо + презентация v2 с одним слайдом результатов + папка аналитики из пяти файлов (без исправленного Excel допустимо приложить исходный, оговорив `#REF!` в README). Тексты — сокращённый вариант раздела 1.
